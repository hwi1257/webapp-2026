📚 [TIL] '상태(State)' 개념 완벽 정리: 3가지 핵심 관점
💡 한 줄 요약
소프트웨어에서 상태(State)란, 프로그램이 실행되는 특정 시점에 쥐고 있는 **'데이터의 현재 모습(스냅샷)'**을 의미합니다.

개발을 하다 보면 '상태'라는 단어를 매일같이 접하지만, 어떤 분야에서 쓰이느냐에 따라 그 의미와 쓰임새가 조금씩 다릅니다. 이를 크게 3가지 맥락으로 나누어 정리했습니다.

🎨 1. UI/프론트엔드 관점 (ex. React)
프론트엔드에서 상태는 화면(UI)의 렌더링을 결정짓는 핵심 트리거입니다.

동작 원리: 데이터(상태)가 변경되면, 프레임워크가 이를 감지하고 화면을 즉각적으로 다시 그립니다(Re-rendering).

상태의 스코프(Scope):

Local State (지역 상태): 특정 컴포넌트 내부에서만 독립적으로 쓰이는 데이터 (예: 모달창 열림/닫힘 여부)

Global State (전역 상태): 앱 전체가 공유해야 하는 핵심 데이터 (예: 로그인한 유저 정보, 테마 설정). 주로 Zustand, Redux, Recoil 등을 활용해 관리합니다.

JavaScript
// Local State 예시 (React)
const [isOpen, setIsOpen] = useState(false); // 모달의 상태
const [user, setUser] = useAtom(userGlobalState); // 전역 상태
🏗️ 2. 객체지향 설계 관점 (State Pattern)
디자인 패턴에서 말하는 상태 패턴은 객체의 내부 상태에 따라 스스로 행동 방식을 바꾸도록 설계하는 기법입니다.

해결하는 문제: 복잡하고 길어지는 if-else 분기문을 없애고, 코드의 유연성과 유지보수성을 높입니다.

적용 예시: 자판기 시스템에서 '동전 투입 전' 상태와 '투입 후' 상태를 각각의 클래스로 분리하여, 똑같은 버튼을 눌러도 상태에 따라 다른 로직이 실행되도록 캡슐화합니다.

⚙️ 3. 시스템 아키텍처 관점 (FSM)
시스템 모델링에서의 상태는 FSM(유한 상태 기계, Finite State Machine) 개념을 통해 예측 가능한 흐름을 만듭니다.

동작 원리: 시스템이 가질 수 있는 상태의 개수를 미리 정해두고(Finite), 특정 조건(Event)이 만족되었을 때만 다음 상태로 넘어가도록(Transition) 설계합니다.

적용 예시: 복잡한 결제 프로세스, 비동기 통신 로직, 게임 캐릭터의 행동 패턴(대기 ➡️ 적 발견 ➡️ 전투 ➡️ 사망) 등에서 로직이 꼬이는 것을 방지합니다.

💡 현업 엔지니어링 꿀팁 & 회고
단순히 변수를 선언하는 것을 넘어, 실제 코드를 작성할 때 고려해야 할 디테일입니다.

직관적인 네이밍 컨벤션 (Naming)

Boolean 타입의 상태값은 누가 봐도 알 수 있게 is, has, should 등의 접두사를 붙여 작성합니다.

❌ bad: const loading = true;

✅ good: const isLoading = true;, const hasError = false;

방어적 프로그래밍과 UX

비동기 통신 시 중간 상태(Loading) 처리는 필수입니다.

데이터를 불러오는 중일 때는 버튼을 disabled 처리하여 유저의 중복 클릭(다중 API 요청)을 막고, 로딩 스피너를 띄워주는 디테일을 챙겨야 합니다.

상태 관리 도구의 적절한 도입

상위 컴포넌트에서 하위로 상태를 무한정 내려주는 **프롭스 드릴링(Prop Drilling)**이 심해지면 가독성이 무너집니다. 이 시점이 바로 전역 상태 관리 도구(Zustand 등)의 도입을 검토할 타이밍입니다.
